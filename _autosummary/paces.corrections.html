paces.corrections#

Human corrections as a replayable log of constraints (issue #10, ADR-0003 §4).

“Ask the user” is a first-class segmenter, and this module is the half of it that decides how an answer survives a re-run: corrections re-enter as constraints for the next run, never as a patch on an output that the next run would overwrite (docs/alignment/07 §7.5).

Two rules from that section shape everything here:

  • Five verbs, constraints only. pin (“it is HERE”), forbid (“it is not there”), absent (“not in this media”), split (“that is two steps”) and merge (“those are one step”). rename is deliberately not a verb: a name is content and belongs in the document layer, which is what lets the log be replayed against a completely different segmenter.

  • Keyed by time, not by step id. anchor_t is a point on the media clock; a step id invented by one run may mean something else in the next, a time does not.

How the log is honoured is a seam on the segmenter, not here: a capability that lists "corrections" in reads receives the log as an input and treats it as solver constraints (the alignment engine, issue #9, will). For every other segmenter, segment() falls back to replay(), which applies the log to the result in order. A correction is **never silently dropped**: one that finds nothing to act on, or that would make the result infeasible, is reported in Segmentation.flags.

>>> from paces.segmenters import segment
>>> log = [split(15.0), merge(20.0)]
>>> seg = segment(boundaries=[0, 10, 20, 30], corrections=log)
>>> seg.boundaries
(0.0, 10.0, 15.0, 30.0)
>>> [s.spans for s in seg.steps]
[((0.0, 10.0),), ((10.0, 15.0),), ((15.0, 30.0),)]

paces.corrections.replay(seg, corrections, *, merge_tolerance_s=1.5, min_step_s=0.25)[source]#

Apply a correction log to a segmentation, in log order.

Each correction acts on the result of the ones before it, as the human made them. Applied ones are flagged corrected: <verb>@<t>; one that finds nothing to act on is flagged correction-unmatched, one that would leave an empty, inverted or overlapping span correction-infeasible (and changes nothing). A forbid is judged against the final placement: satisfied: forbid@<t>, or correction-unenforced — moving a step elsewhere needs a solver, which replay is not. A pin that clips a child step out of existence says so (correction-clipped). A last consistency pass flags (inconsistent:) any empty span, any overlap between steps, and any step edge missing from boundaries.

>>> seg = Segmentation(steps=(SegStep(id="a", spans=((0.0, 10.0),)),),
...                    boundaries=(0.0, 10.0))
>>> replay(seg, [split(5), split(5.1)]).flags
('corrected: split@5', 'correction-unmatched: split@5.1 (within 0.25 s of a cut)')
Return type:

Segmentation
